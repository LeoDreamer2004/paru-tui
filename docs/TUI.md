# Paru TUI

此 fork 新增原生 Rust TUI 入口，使用 ratatui / crossterm。原始 `paru` CLI 保留。

## 构建与运行

需要 Arch Linux 的 Rust 工具链、libalpm（pacman）、Git 和 paru 原有构建依赖。

```sh
cargo build --release --features tui --bin paru-tui
./target/release/paru-tui
```

以普通用户启动；实际事务需要权限时由后端请求。建议终端至少 100×30，最低 62×18。默认背景跟随终端主题。

`Enter` 在更新页的 AUR 栏仅选择当前包（`-S --aur <包>`），由 paru 补齐必要依赖；不会选择其他 AUR 更新，代理规则仍生效。官方栏的 Enter 不执行单包更新。

`u` 在官方栏执行 `-Syu --repo`，在 AUR 栏执行 `-Sua --devel`；`a` 执行 `-Syu --devel`。这表示更新整个来源，不是仅更新光标所在的包。忽略包和依赖处理沿用 paru 配置。安装单个搜索结果使用 `-S -- <来源>/<包名>`，沿用当前同步数据库和 paru 的依赖处理。搜索不刷新系统数据库。

顶部系统栏已移除。更新、设置和活动页没有状态栏，仅必要操作提示与报错通过右上角圆角通知平移进出，动画期间约每 16 ms 刷新；下载进度以更新页下方的紧凑进度条显示，常规后端事件只记入 Activity，不再弹窗。List 页提供本地过滤，Install 页提供官方仓库与 AUR 搜索。更新页焦点顺序为 Pacman → AUR → Inspector → 输出区；查看页为 Installed → Inspector，安装页为结果列表 → Inspector → 输出区。Shift+Tab 反向切换，左右键不再切换来源。焦点不会随后台更新跳转。

界面使用弱化的非焦点边框、青色焦点和轻微选中底色。包列表每包一行，按列显示版本，窄栏省略旧版本（完整版本仍在 Inspector）。Inspector 按版本与来源、安装、依赖、构建与链接分组；底栏仅保留当前焦点的常用操作。

配色统一采用 Arctic 的灰、青、蓝层级，成功为绿色、错误为红色。打开确认或帮助弹窗时，背景文字会变暗，终端默认背景仍保留。面板焦点约 110 ms 渐变；列表背景条与视口采用约 140 ms 三次 ease-out 非线性缓动，上下保留最多三行阅读缓冲。快速连续按键从当前动画位置继续，实际选择和操作目标立即更新。Kitty 直连终端且提供字符像素尺寸时，列表使用 Rust 字体栅格化与图形层，文字、背景条和三角指示符共用滚动位置，按像素同步移动；文字主题色按背景条的实际像素区域裁切，不会提前跳到目标行；普通终端、tmux / screen、缺少像素尺寸或无法加载字体时，文字使用原生终端渲染。动画期间约每 16 ms 刷新，静止时恢复常规刷新频率。

列表右侧提供细滚动条，底部显示所选项位置；超出可视范围的详情、活动日志和弹窗内容也提供滚动条与当前阅读范围。只构造可见包列表行，动画不会遍历整个软件包目录。图像列表缓存可见行（上限 16 MiB / 512 行），静止时不重复传输图像；弹窗与通知会遮挡图像，缩放时重建像素布局。详情字段换行后对齐内容列，可选依赖逐项换行，保留搜索高亮。

通知与确认内容跟随界面语言，构建文件原文保持不变。更新确认附带带提示符和语法着色的 `paru` 命令块；sudo 使用独立密码卡片，支持 `Ctrl+U` 清空。失败时保留 sudo 等后端的具体诊断。活动页以时间戳、INFO/WARN/ERROR 等级和正文显示记录，错误为红色，警告为黄色。

顶部使用圆角导航条与 PARU 标识，胶囊背景在标签之间移动。帮助页区分主题色标题、按键与灰色说明。可选依赖的补充说明为灰色，网络状态采用 `DIRECT (Git follows settings)` / `PROXY (package base)`，括号说明为灰色。

设置页右侧跟随当前选项显示详情：代理地址格式及软件包规则、Git 代理范围、界面语言说明和主题色预览。主题色提供青绿、天蓝、浅紫、玫粉、琥珀五种预设；Enter / 空格循环选择并即时保存，成功与错误仍使用绿、红色。`PgUp/PgDn` 滚动长详情，切换设置项后回到顶部。

图像列表需要 fontconfig 和可用的等宽字体；优先读取 Kitty 配置中的 `font_family`，通过 fontconfig 补充中文和符号字体。可用 `PARU_TUI_FONT` 指定字体族。字形按原始宽高比例渲染，以主字体的等宽步进匹配终端字符格；回退字体共用 em 字号并居中，不会独立拉伸横纵轴。图像列表不能直接通过终端选中文字，字体抗锯齿可能与 Kitty 原生文字略有差异。

## 更新查询与性能

- 直接读取 libalpm 数据，不解析 `paru` 的列表输出。
- 后台先展示本地缓存，使用 paru 克隆目录中的 `.SRCINFO` 识别已安装的 AUR 包，再在临时目录刷新官方数据库并分批查询 AUR。AUR 批量查询失败时保留已识别的来源；浏览不会对系统数据库执行 `-Sy`。
- 右上角通知提示扫描状态与缓存回退；错误详情可在 Activity 查看。
- 本地搜索使用缓存并高亮匹配；每帧只构造可见列表行。空的 AUR 搜索分栏已移除。
- 查看页列表 / Inspector 的宽度为 38% / 62%，更新页的比例保持不变。详情延迟按需加载并缓存，包括架构、许可证、组、可选依赖、提供/冲突/替代、反向依赖、打包者、构建/安装日期、安装原因、验证方式、安装脚本和备份文件。
- 列表是**候选预览**，实际执行仍重新解析依赖和更新计划。
- 扫描同时读取 paru 的 `devel.toml`，对已跟踪的 AUR 包比较 Git 远端提交；发生变化显示 `latest-commit`。按 pkgbase 关联拆分包，不依赖名称是否以 `-git` 结尾。遵循忽略包、IgnoreDevel 和 IgnoreDevelSource 设置。
- Git 检查最多并发 8 个请求，每个请求超时 15 秒；失败会报告具体源，不会误报无更新或把空提交当作更新。扫描不改写已安装提交的基准。AUR / 全部更新显式启用 `--devel`，所选 Git 更新也启用它。尚未被 paru 跟踪的源码包需要先建立 devel 记录（例如 `paru --gendb`）。

## 依赖树

列表页按 `t` 进入依赖树，默认折叠显示不被其他已安装包依赖的顶层包；再次按 `t` 返回平铺。树只显示软件包名和已安装版本，不显示来源。淡灰色 `│` / `├─` / `└─` 表示层级，`▸` / `▾` 表示折叠状态。展开、移动和滚动复用原有像素动画，右侧详情与 `d` 删除始终对应当前节点。

关系来自本地 libalpm 数据库，只包含已安装的必需运行依赖；版本约束和虚拟 provides 由 libalpm 解析，可选依赖仍在详情查看。共享依赖可在多个分支出现，并独立展开。实际包关系可能有环：循环引用以 `↩` 标记并停止展开；没有普通根的循环组以一个代表包作为入口，避免漏包。

搜索时匹配的软件包作为临时根，仍可展开其完整依赖；`Esc` 恢复顶层视图。图只在扫描时构造，可见树只在筛选或展开状态变化时重建，每帧仅绘制屏幕内的行。

## 搜索与安装

进入安装页默认聚焦列表，按 `/` 才进入搜索输入。安装页复用 paru 的官方仓库与 AUR 搜索函数（对应 `paru -Ss`），先显示官方结果，再补充 AUR。仅处理最新查询，旧请求会取消，迟到结果不会覆盖新搜索。AUR 查询失败时保留官方结果，错误显示于通知和活动记录。

左侧按软件包名、来源、更新日期排列，右侧显示详情；底部复用更新页的下载进度、构建输出和焦点操作。官方同步数据库可提供描述、版本、架构、依赖、许可证、大小、打包者、构建日期等。未安装包没有本机安装日期、安装原因和反向依赖；列表日期采用仓库的**构建日期**，详情明确说明日期来源。AUR 日期为最后修改时间，选中后延迟获取依赖等完整 RPC 信息。

无人维护（孤儿包）与已标记过期的 AUR 包在详情顶部显示固定红框，滚动时仍可见；`o` 通过 `xdg-open` 打开详情中的 AUR 网址。安装复用原生确认、PKGBUILD 审阅、sudo 密码和事务计划；没有确认就不会开始安装。`v` 打开左右双栏只读阅读器：左侧优先显示 PKGBUILD，右侧异步逐页加载全部 AUR 评论（含置顶评论）。评论之间用分隔线区分，作者和日期分层着色；代码块是带内边距的整行灰底区域，网页链接可左键点击打开。`Tab` / `←→` 切换栏，`↑↓`、`PageUp/PageDown` 和鼠标滚轮滚动，`Esc` 或 Enter 关闭；详情、帮助、活动记录和构建输出也支持鼠标滚轮。

## 删除软件包

在列表页选中已安装包，按 `d` / `Delete`。先出现删除方式复选框，`↑↓` / `Tab` 移动，`Space` 勾选，`Enter` 进入带命令行的确认框；两步均可用 `Esc` 取消。默认勾选 `-s`、`-ss` 和 `-c`，即 `paru -Rssc -- <包名>`；`-n` 与 `--unneeded` 默认不勾选。可取消勾选以使用其他组合。

- `-s`：清理不再被其他包依赖、且作为依赖安装的包。
- `-ss`：也清理不再被需要的显式安装依赖；勾选时自动启用 `-s`。
- `-c`：级联删除依赖目标包的软件，可与 `-s` 组合成 `-Rsc`。
- `-n`：不生成包管理器的 `.pacsave` 配置备份，不涉及用户目录配置。
- `--unneeded`：跳过仍被其他包依赖的目标，与级联删除互斥。

选项语义参照 [pacman 删除选项](https://man.archlinux.org/man/pacman.8.en#REMOVE_OPTIONS_(APPLY_TO_-R))。确认命令后仍需审阅 libalpm 生成的实际删除清单和释放空间，接受计划后才执行。删除完成后自动刷新已安装列表。

安装列表的软件包名列缩窄，为状态标记和日期右侧留白预留空间。已安装的软件包名称显示为绿色，并在名称前标注 `✓`；选中时仍保持绿色，过期或无人维护的状态标记继续使用红色。AUR 已标记过期显示红色 `[旧]`，无人维护显示红色 `[孤]`；英文界面对应 `[old]` / `[orphan]`。这些状态来自 AUR，不凭发布时间推断是否过期；红色语义在选中和动画过程中保持不变。

## 代理

配置文件为 `$XDG_CONFIG_HOME/paru-tui/settings.toml`（默认 `~/.config/paru-tui/settings.toml`），以 0600 权限原子写入。例如：

```toml
language = "zh-cn" # 或 "en"
accent = "teal" # teal / blue / purple / pink / amber
proxy_url = "socks5h://127.0.0.1:1080"
git_proxy = false
proxy_bases = ["example-git"]
```

先配置地址，再在更新、安装或列表页的 AUR 包上按 `p`。地址可以直接输入 `127.0.0.1:7890`，保存时会补为 `http://127.0.0.1:7890`；SOCKS 代理请显式填写 `socks5h://`。编辑时 `Enter` 保存并退出编辑、`Esc` 放弃、`Ctrl+U` 清空；无效地址会在输入框旁显示错误。规则绑定 **pkgbase**，同一个 PKGBUILD 产生的拆分包共享规则。每次事务使用启动时的配置快照。

设置页的“清理缓存”会先展示命令确认，再运行 `paru -Scc`。pacman 的删除缓存文件、清理无用仓库数据库两个原生提问会逐一显示为 TUI 弹窗，并将选择交回 pacman；之后 paru 对 AUR 克隆和已保存差异的提问也在 TUI 中处理。某一清理阶段失败后仍继续询问并执行后续阶段，最后汇总失败；用户主动取消则停止。

- 标记的 pkgbase：PKGBUILD 的 Git 操作、makepkg 进程及其继承环境的下载工具使用代理。
- 未标记的 pkgbase：清除继承的常用代理环境变量，按直连策略执行。
- 全局 Git 开关：扫描更新时的 `git ls-remote`，以及工作进程中的 Git 操作统一使用配置代理，包括未标记包的 Git 源；不把这些包的全部构建下载也改为代理。关闭全局开关时，已标记 pkgbase 的 Git 扫描仍使用单包代理规则。扫描使用启动时的设置快照；更改代理后按 `r` 重新扫描。
- 支持 HTTP(S) 和 SOCKS5(h) 代理 URL。需要代理的 SSH / git 协议远端不受支持时会报错；建议使用 HTTPS 远端。
- 当前策略作用于构建和 Git；官方镜像下载与共享 AUR 元数据请求仍沿用 paru / 系统网络配置。
- 这不是网络隔离：自行联网且忽略代理环境的 PKGBUILD、绝对路径调用的 Git、自定义 Git URL/remote 代理配置需要单独检查。启用代理规则时不支持 chroot 构建，会在执行前拒绝。

## 原生交互与事务

已经移除 F8 兼容模式。TUI 不通过识别 pacman 文本、模拟终端回答或添加 `--noconfirm` 来执行更新。

- paru 的确认、输入、提供者和包组选择使用结构化消息。
- PKGBUILD 及其修改内容在原生滚动弹窗中审阅和确认（新增绿色、删除红色，文件头和区块标题分别着色），不再调用 less / FileManager。当前审阅为只读，修改文件后需重新发起操作。
- sudo 通过 askpass 独立通道请求密码，输入显示为掩码，不写入构建终端或活动记录。
- 官方同步安装、AUR 本地归档安装、删除和安装原因更新由独立工作进程直接调用 libalpm。需权限时通过 sudo 启动同一二进制的事务入口。
- pacman 下载直接读取 libalpm 回调，在更新页下方显示总进度与并行文件进度、已下载大小和平均速度；重试更新原条目，完成项压缩显示，构建开始时切换回构建输出。
- libalpm 完成 prepare 后，将实际包清单、下载大小、安装大小和净变化发送至 TUI。更新、安装及准备完成后的事务确认默认选中“是”，仍需按 Enter 提交。用户确认期间保留数据库锁，确认后提交同一个事务；取消、拒绝或断连均释放事务。
- 依赖提供者、忽略包、替换、冲突、损坏文件及签名密钥问题通过原生回调处理。进度和错误作为后端消息显示。
- Updates 底部的终端仅接收 makepkg 包构建阶段的输出，保留最近一个构建的滚动历史，不显示其他包管理命令输出。它当前是只读日志视图。

语言设置即时生效并持久保存，支持中英文界面。软件包描述、构建内容和部分底层诊断保留原文。

当前原生事务尚不覆盖 paru 的所有 CLI 扩展：chroot 构建、非 sudo 授权、XferCommand、直接远程 URL 安装及未实现的事务参数会明确失败，不回退到交互终端。保留的 `paru` CLI 不启用这些 TUI 路径。提交过程中中断会等待 libalpm 返回，避免在文件变更中途强行退出。
